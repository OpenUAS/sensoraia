    Detailed Description

    C implementation of frame-clock conversion and capture EXIF setup.

    Sampling MONOTONIC on both sides of BOOTTIME bounds offset-read latency. Implausible sensor age, duration or sampling cost leaves the original evidence available but keeps its alignment timestamp explicitly unqualified.

    struct usher_frame_timing usher_frame_timing_estimate ( uint64_t sequence,
    uint64_t sensor_ns,
    int64_t exposure_us,
    int64_t duration_us )

    Translate fresh sensor evidence into a cautious pose-alignment time.

    Parameters
    sequenceCamera sequence belonging to this exposure.
    sensor_nsSensor timestamp in the local BOOTTIME domain.
    exposure_usExposure duration in microseconds; accepted range 0..100000.
    duration_usFrame duration in microseconds; accepted range 1..200000.
    Returns
    Original evidence plus an estimated midpoint and uncertainty, or unqualified defaults when clock sampling or plausibility checks fail.

    Bracketing BOOTTIME with MONOTONIC samples avoids assuming equal clock origins, including after suspend. The returned record is a value, so callers can retain it with the exact frame without allocation or shared state.

    Warning
    Sensor timestamps must follow BOOTTIME. Frame duration is not a measured rolling-shutter readout time; this estimate alone proves neither shutter synchronization nor geolocation accuracy.
