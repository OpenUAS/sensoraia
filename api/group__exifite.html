    Detailed Description

    Small, caller-owned EXIF documents and borrowed metadata views.

    Use separate storage for concurrent operations. The core has no mutable global state; sharing a document or stream still needs caller-side synchronization. File publication and path ownership belong to image_exif.c.

    ◆ exif_read_jpeg()

    int exif_read_jpeg ( const char * filename,
    unsigned char * payload,
    size_t capacity,
    size_t * size )

    Read the single EXIF APP1 segment before the first JPEG scan.

    Parameters
    [in]filenameNUL-terminated path to a readable JPEG.
    [out]payloadCaller-owned writable payload buffer.
    [in]capacityAvailable bytes in the payload buffer.
    [out]sizePayload length on success, otherwise zero when non-NULL.
    Returns
    Zero on success, otherwise -1 with errno describing the failure.

    Metadata lookup stops before compressed image data to keep reads cheap. Duplicate EXIF is rejected rather than guessing which record is authoritative. Header work is bounded by marker and segment-byte limits.

    Precondition

    Warning
    This extracts bytes, not a validated TIFF view or a fully validated JPEG. Call exif_parse() before interpreting the payload; ignore its contents on failure.

    Stream a JPEG with one new EXIF segment instead of its old EXIF records.

    const unsigned char * payload,

    Replace EXIF in a regular JPEG file without a temporary file.

    Parameters
    [in,out]fileRead/write binary stream positioned at byte zero.
    [in]payloadComplete valid EXIF APP1 payload outside the stream buffers.
    [in]sizeAccessible payload byte count, at most EXIF_MAX_PAYLOAD.
    Returns
    Zero on success, otherwise -1 with errno set.

    The entire framing is validated before mutation. Bounded block moves retain compressed bytes, unrelated markers and trailing data. Equal-size spans are not rewritten. No JPEG-sized memory or disk copy is created.

    Precondition
    The caller exclusively owns the file and any hard-linked aliases.
    Warning
    Not atomic: write failures or interruption after mutation starts can leave a damaged JPEG. Success flushes but does not sync or close the file.
