    Detailed Description

    Command-line entry point of the lwircam executable.

    One binary serves several mutually exclusive roles, selected by options:

    • One-shot capture (default): main() forks; the child runs save_capture() while the parent supervise()s it against a monotonic deadline, so a wedged USB/UVC call cannot outlive timeout_ms.
    • Persistent capture server (--capture-server): serve_captures() keeps the camera streaming and answers one absolute output path per stdin line. This is the interface USHER drives.
    • Raw replay (--raw FRAME --size W H): renders a recorded frame through the same statistics/JPEG/publication path, marked as simulated.
    • Standalone camera controls (--get-control, --set-gain, --set-emissivity-128, --set-agc-mode, --set-agc, --ffc): exactly one control per invocation, no image output.
    • Optional builds: analysis builds add --analyze, --check-model, --calibration and --geolocate; mock builds add --mock-image and --mock-layer. Those options are rejected in builds without the feature.

    Capture data flow:

    1. Acquire a frame (camera via lwir_device, or replay file) into the static captured_frame buffer. Freshness is measured from the start of the request, so a published photo is never older than the request.
    2. Optionally read device state (--device-state): opt-in, read-only, after the frame (not frame-atomic) and bounded to 250 ms.
    3. Optionally compute temperature statistics/threshold coverage.
    4. Hash the frame bytes (SHA-256) into the evidence record.
    5. Optionally write a raw companion (--record-raw or --native-raw, which derives PATH.raw) for byte-exact verification.
    6. Encode the JPEG with evidence metadata; the temperature plane is stored exactly in APP15 markers. Capture defaults to quality 95 with 4:4:4 sampling (0 in the library means legacy quality 100).
    7. Publish durably without overwriting: the image library writes a temporary file, fsyncs it, link()s it to the final name (fails if it exists) and fsyncs the directory. main() also refuses an existing output up front.

    Configuration precedence: the settings INI (--settings/--config, or the discovered default lwircam settings file) is loaded first, then command-line options override or extend it. Each INI key may appear only once.

    Exit codes: 0 success; 1 runtime failure; 2 usage/configuration error (including capture-server protocol violations); 124 supervisor timeout; 128+signal when interrupted by SIGINT/SIGTERM.

    Memory policy: no heap in this file and no memcpy (project policy); strings are copied with bounded loops into fixed static storage.

    ◆ publish_frame()

    bool publish_frame ( struct capture_options * options)
    		static

    Validate, hash and durably publish captured_frame.

    Refuses publication when a correction profile disagrees with the device gain readback or with the serial/gain label/geometry, because applying the wrong profile would silently corrupt temperatures.     ◆ serve_captures()

    int serve_captures ( struct capture_options * options)
    		static

    Persistent --capture-server loop driven by USHER over stdin/stdout.

    Protocol:

    • After the camera (or replay frame) is ready, prints LWIR_SERVER_READY.
    • Each stdin line is an absolute output path, or GEO:path to geolocate an existing JPEG in analysis builds.
    • A capture replies LWIR_SERVER_TIMING request_us arrival_us then LWIR_SERVER_OK; a geolocation replies LWIR_SERVER_OK only.
    • Strictly one request at a time: bytes after the newline (pipelining), embedded NULs, control characters, relative or overlong paths are protocol errors (result 2).
    • Any failure prints LWIR_SERVER_ERROR and ends the server. There is no automatic replay; USHER's supervisor must explicitly restart it.

    While idle, stdin is polled every 10 ms and camera frames are discarded so the 4-buffer driver queue never hands a stale frame to the next request; if no frame arrives for timeout_ms the server fails. Each request has an alarm() hang watchdog of timeout_ms rounded up to seconds: SIGALRM is not handled, so a wedged request terminates the process.

    warmup_ms is forced to 0 per request: startup qualification happens once per USB power instance (tracked by the device layer's driver marker), never per request.

    Parameters
    [in,out]optionsPolicy; output and record_raw are rewritten per request.
    Returns
    0 when stdin reaches EOF cleanly; 1 runtime failure; 2 inference configuration, correction-profile mismatch (before READY) or protocol error; 128+signal when interrupted.

Publication may already have happened, or be half-done, when the child is stopped, so the outcome is reported as ambiguous and nothing is retried automatically. A failing clock is treated as an expired deadline (fail safe).
