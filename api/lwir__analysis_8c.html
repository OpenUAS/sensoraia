    Detailed Description

    Serial saved-image analysis adapter, not part of the camera driver.

    Built only when LWIR_ENABLE_ANALYSIS=1. Works on an already saved LWIR JPEG: extracts the embedded exact Kelvin*64 temperature plane, detects hotspots, reads the observation pose from EXIF ImageDescription, optionally projects each hotspot to the ground, and writes a text record into EXIF UserComment. The entropy-coded display image is not decoded or recompressed.

    Memory: large buffers are file-scope statics (no heap, no large stack frames apart from the 8 KiB record and EXIF payload copy in read_pose()), which is why the adapter is strictly serial.

    ◆ lwir_geolocate_image()

    int lwir_geolocate_image ( const char * filename,
    const char * calibration_path )

    Detect, optionally geolocate and record hotspots for one saved JPEG.

    Annotate a saved thermal JPEG without recompressing its display pixels.

    See lwir_analysis.h for the contract. Order of evaluation:

    1. Read the embedded temperature plane: invalid -> status=invalid_native_frame; absent -> status=no_temperature_plane (both published, return value from publishing).
    2. Read pose and calibration (each may be missing without aborting).
    3. Detect hotspots, then derive a single status with precedence missing pose > missing calibration > invalid calibration > unverified calibration, finally overridden by no_hotspots.
    4. For each hotspot, report the rounded pixel, its nearest-pixel temperature and the subpixel projection input; project only when status is estimated.
      Returns
      0 when a record was published, -1 otherwise.

    ◆ publish_hotspot_comment()

    int publish_hotspot_comment ( const char * filename,
    const char * information )
    		static

    Rewrite a JPEG's EXIF with the analysis record, keeping image data intact.

    Opens with O_NOFOLLOW and requires a regular file, so a symlink cannot redirect the write. Existing EXIF is imported (ENODATA means none, which is acceptable); other read/parse failures abort rather than discard metadata.

    With IMAGE_EXIF_ATOMIC_REPLACE the JPEG is streamed to a sibling mkstemp() file (same directory, so rename() stays atomic on one filesystem) with the original permission bits, fsync()ed, and renamed over the original only if the path still names the same inode (dev/ino), so a concurrently replaced file is not clobbered. Otherwise the EXIF segment is updated in place.

    Parameters
    filenameTarget JPEG path.
    informationNUL-terminated analysis record.
    Returns
    0 on success, -1 on any open, stat, EXIF, write, sync or rename failure (errno may reflect the failing call; not guaranteed).
    Note
    The containing directory is not fsync()ed after rename(), so the rename itself may not survive a sudden power loss.
    Warning
    In-place mode cannot roll back a partially written update.

    ◆ read_pose()

    bool read_pose ( const char * filename,
    struct lwir_camera_pose * pose )
    		static

    Read the observation pose recorded in a saved image's EXIF ImageDescription.

    The description is a key=value; key=value list written at capture time. Segments end at ';' or NUL; segments without '=' and unknown keys are ignored, but a duplicated known key or an unparsable number rejects the whole pose rather than guessing which value is right.

    Required: lat_deg, lon_deg, alt_m (WGS84 ellipsoidal height, as sent by the flight controller), roll_deg, pitch_deg, yaw_deg, and either altitude_agl_m or groundalt_m. Both carry height above ground: USHER's groundalt_m is the flight controller's groundalt field, which Paparazzi fills with altitude above ground, not the ground's own altitude. When both are present altitude_agl_m wins.

    Timing qualification: synchronized is true only when capture_pose_synchronized=true, observation_time_kind names an exposure-bounding interval, and a non-negative pose_uncertainty_m is present. Any other time kind (for example a plain arrival time) leaves it false.

    Parameters
    filenameSaved JPEG to read; opened independently of the publisher.
    [out]poseWritten only on success; angles converted to radians.
    Returns
    True when a complete pose was parsed; false when EXIF or the description is absent/malformed or required keys are missing. Callers treat false as "missing pose", never as a zero pose.
    Note
    Uses a stack copy of the EXIF payload (EXIF_MAX_PAYLOAD bytes).

    ◆ set_hotspot_comment()

    bool set_hotspot_comment ( const char * information)
    		static

    Store the analysis record in the in-memory EXIF document's UserComment.

    Layout: the 8-byte EXIF character-code prefix ASCII\0\0\0, the original ImageDescription text (so pose evidence is visible in one field), a \nLWIR_HOTSPOTS_V1\n version separator, the record, and a terminating NUL. The description is copied out first because exif_document_reserve() can move existing values that description.data borrows.

    Parameters
    informationNUL-terminated record, at most 8192 characters.
    Returns
    True when the tag was reserved and filled; false for an oversized or non-ASCII-format description, an oversized record, or exhausted document capacity (errno ENOSPC/EINVAL from exif_document_reserve()).
    Note
    exif_document_reserve() replaces an existing UserComment, so re-running analysis overwrites rather than stacks records.
