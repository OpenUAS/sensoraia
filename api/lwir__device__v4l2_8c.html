    Detailed Description

    Native Linux UVC acquisition with bounded mapped-buffer ownership.

    Implements lwir_device.h directly on the kernel uvcvideo driver through V4L2 MMAP buffers and Linux usbfs control transfers.

    Cameras
    • Tiny1-C, USB 0bda:5840: YUYV transport 256x384 = 256x192 image plane followed by a 256x192 temperature plane (Kelvin*64, little-endian), 196608 bytes per frame at 25 fps (LWIR_COMBINED).
    • TDK, USB 5474:5411: 640x512 YUYV image only (LWIR_YUYV_IMAGE).
    How the pieces fit
    1. Discovery (video_probe(), video_identity()) maps a /dev/videoN node to its USB device through sysfs, checks vendor/product/serial and takes an exclusive non-blocking flock so no second process (for example a control command while USHER captures) can share the camera.
    2. Setup (video_setup()) negotiates the exact native format and maps LWIR_VIDEO_BUFFERS MMAP buffers, then starts streaming.
    3. Acquisition (lwir_device_acquire()) polls in 25 ms slices, dequeues a buffer, validates it, copies it if accepted and always requeues it.
    4. Startup qualification is persisted per USB power instance by a runtime marker (video_power_marker()).
    5. Optional Tiny1-C state/control uses vendor control transfers over usbfs (video_state_open(), video_state_transfer()) beside the running stream.
    Buffer ownership
    A mapped buffer belongs to user space only between VIDIOC_DQBUF and VIDIOC_QBUF. Everything needed from it (pixels, sequence, timestamp, flags) is copied or snapshotted before requeue: after QBUF the kernel may refill the memory and the driver may rewrite buffer metadata at any moment. This ordering was required by a real hardware fault, not by theory.
    Failure model
    Fatal kernel or protocol errors set lwir_device::video_failed, poisoning the session until close and reopen; partial recovery of a V4L2 queue in an unknown state is not attempted. A failed munmap keeps ownership so a later close retries it and open refuses with EBUSY. close() is never retried because Linux releases the descriptor number even on error, and another thread may already have reused it.
    Startup qualification
    The first power-up of the camera needs eight consecutive valid frames. Linux exposes no sensor power-cycle counter, so a fresh USB enumeration is the observable power boundary: the marker /run/lock/sensoraia-lwir-UID/usb-PORT.ready stores "bootid:sysfs-inode:busnum:devnum". Qualification is never repeated for later requests, sequence gaps, bad frames, reopen or worker restart within the same instance. Marker failures are explicit errors rather than a silent fallback to another warmup.
    Freshness and latency
    A frame is accepted only when its kernel CLOCK_MONOTONIC timestamp (taken by uvcvideo at start of frame) is not earlier than the request, so the photo never predates the trigger. Measured cost is about 8.6 ms average wait for the next frame start plus about 36.1 ms USB delivery; that is the sensor/USB limit, not overhead of this code. For non-MONOTONIC clocks the already-queued buffers are drained once instead.
    Policies
    • No heap allocation; all state is in the caller's struct lwir_device.
    • No memcpy by project policy: bounded byte loops are used. Compilers vectorize them; -fno-tree-loop-distribute-patterns stops them from being turned back into memcpy calls.
    • Interrupted system calls are retried a bounded number of times so a signal storm cannot spin forever.
    Threading
    Single-threaded per session. Only the borrowed cancellation flag is read asynchronously.

    Wait for, validate and copy the first acceptable frame that started after this call.

    Copy a qualified, fresh camera-layout frame into caller-owned storage.

    Loop structure, each iteration bounded by a 25 ms poll() slice so that cancellation and the deadline are noticed promptly:

    1. poll() for a filled buffer; POLLERR/POLLHUP/POLLNVAL (for example an unplugged camera) poison the session.
    2. Dequeue one buffer and read the host clock immediately.
    3. Grade the frame in increasing strictness:
      • usable: structurally valid, recent, correct sequence; feeds the startup qualification counter even when it predates the request.
      • valid: additionally started at or after the request (freshness).
      • scene_valid: additionally passes the optional scene check.
    4. For non-MONOTONIC clocks freshness is unknowable, so the first good frame triggers a one-time drain of all already-queued buffers; the next frame is then certainly produced after the request.
    5. Accept when the instance is qualified (eight good frames), optional settling holds, and on first startup only, warmup_ms has elapsed.
    6. Copy what is needed and snapshot sequence/timestamp/flags, then requeue. The order matters: after QBUF the kernel may overwrite both pixels and metadata.
    7. Persist the startup marker once qualification and warmup are complete.

    Settling uses destination as the previous-image store: the image plane of each scene-valid frame is copied there and the next frame is compared against it, so no extra buffer is needed. The temperature plane is copied only for the accepted frame.

    Returns
    True with a fresh frame in destination.
    Errors
    EINVAL arguments/aliasing; EIO poisoned session or poll error; ETIMEDOUT deadline, including completion that would land after it; EINTR cancelled; kernel errno from failed ioctls (session then poisoned).
    Warning
    On failure destination may contain partial or settling data and must be ignored.

    ◆ lwir_device_close()

    void lwir_device_close ( struct lwir_device * device)

    Release a session in the reverse order of setup.

    Close an initialized session; safe repeatedly and preserves errno.

    1. STREAMOFF returns all buffers from the driver queue to user space.
    2. munmap each mapping. A failed unmap keeps its entry marked as mapped and the session struct is not cleared, so a later close retries it and lwir_device_open() refuses with EBUSY rather than losing track of memory the process still maps.
    3. REQBUFS with count 0 frees the kernel buffers when the driver allows it.
    4. close() the descriptor exactly once. Its state is cleared first and a close error is only logged: Linux frees the number even on error, so retrying could close an unrelated descriptor opened by another thread.

    Errors of STREAMOFF/REQBUFS are deliberately ignored; there is no better recovery than continuing teardown, and closing the descriptor ends the stream regardless.

    Parameters
    deviceSession to release; NULL and already-closed sessions are accepted.
    Note
    errno is preserved so callers can close on an error path without losing the original cause.

    ◆ lwir_device_open()

    bool lwir_device_open ( struct lwir_device_options * options,
    struct lwir_device * device )

    Find, lock and start exactly one supported camera within the timeout.

    Open/start a bounded camera-specific combined or image-only YUY2 stream.

    1. Validate options and refuse while the session still owns anything, including mappings kept after a failed munmap (EBUSY).
    2. Compute one absolute deadline covering discovery and setup.
    3. With an explicit device path, probe only that node. Otherwise probe /dev/video0..63. A second matching camera is an error (EEXIST) rather than "first wins": with two cameras attached the choice would depend on enumeration order, so the caller must disambiguate with a serial or path. Each match holds its own flock until the scan decides.
    4. Read the startup marker, then set up streaming.

    Every failure after a successful probe closes the session, so the caller never has to clean up after a false return.

    Returns
    True when streaming; errno set otherwise (see lwir_device.h).

    Resolve a V4L2 character device to its USB camera identity through sysfs.

    1. /sys/dev/char/MAJOR:MINOR/device points at the USB interface that owns the video node; it is canonicalized with realpath().
    2. Walk up at most 16 directories to the first ancestor exposing idVendor/idProduct, which is the USB device itself. The first such ancestor decides: an unsupported vendor/product is rejected rather than walking further up to a hub.
    3. The last path component is the physical port name (digits, '-' and '.'), which is stable across re-enumeration and so names the marker.
    4. Build the power key from boot_id, the sysfs directory inode, busnum and devnum. A new boot, a new enumeration (new sysfs node, new address) or a different bus all change the key; that is how a sensor power cycle is detected without any counter from the camera.

    Bus and address are range-checked because they later form the usbfs path /dev/bus/usb/BBB/DDD and its expected device number (USB addresses are 1..127).

    Parameters
    nodestat() of the video node; must be a character device.
    layoutOutput: layout implied by vendor/product.
    serialOutput: USB serial or empty string.
    power_keyOutput: power-instance key (see above).
    power_portOutput: USB port name.
    usb_busOutput: USB bus number.
    usb_addressOutput: USB device address.
    Returns
    True when the node belongs to a supported camera.
    Errors
    ENODEV not a supported camera or no USB ancestor; EPROTO malformed bus or address; EOVERFLOW key too long; other errno from realpath/stat/sysfs reads.
    Note

    bool video_power_marker ( struct lwir_device * device,
    bool complete )
    		static

    Read or publish the per-USB-instance startup qualification marker.

    The marker /run/lock/sensoraia-lwir-UID/usb-PORT.ready holds the power key of the USB instance that already completed eight-frame qualification. /run is normally tmpfs, so a reboot clears it; boot_id inside the key covers the case where it does not.

    Security and integrity checks: the directory must be a real directory owned by the effective user with no group/other access, and the marker a regular single-link file with the same ownership. All opens use O_NOFOLLOW and *at() calls relative to the verified directory descriptor, so a symlink or hard link planted by another user cannot redirect or spoof the marker.

    Read mode (complete false): a missing marker means "not yet qualified"; a marker with a different key (an earlier power instance) likewise. A matching key restores eight good frames so no wait is imposed after reopen or worker restart.

    Write mode (complete true): the key is written to usb-PORT.pending, created with O_EXCL, and renamed over the .ready file. rename is atomic, so a concurrent reader or a crash sees either the old or the new complete marker, never a partial key.

    Any failure is returned as an error instead of being treated as "not ready": a silent fallback would quietly impose a new warmup on a camera that does not need one and hide a broken runtime directory.

    Parameters
    deviceSession supplying the power key and port; video_power_ready and possibly video_good_frames are updated.
    completeFalse to read, true to publish completion.
    Returns
    True on success (including "no marker" in read mode).
    Errors
    EINVAL missing key/port; EACCES unsafe ownership, mode or link count; EOVERFLOW name too long; EPROTO embedded NUL; EIO unexpected EOF/short write; other errno from mkdir/open/read/write/rename/close.
