    Detailed Description

    Display rendering of Tiny1-C frames into JPEG-ready Y/Cb/Cr scanlines.

    Rendering is strictly a display concern: it reads an immutable combined frame (see lwir_frame.h) and never reorders, rewrites or calibrates the stored raw thermal bytes, so measurements and saved data stay in native coordinates.

    Workflow per frame: lwir_render_prepare() validates options and resolves one display window (struct lwir_render_range); lwir_render_dimensions() gives the oriented size; lwir_render_row() is then called once per display row to fill a caller-owned buffer of display_width * 3 bytes, so no full RGB or rotated frame is ever materialized.

    Views: LWIR_SENSOR passes the camera's own YUYV image through; LWIR_FIXED maps an operator raw window; LWIR_PERCENTILE derives the window from the frame's histogram. Thermal views map the window through a palette, flag below/above/invalid samples with distinct colours, and may draw a legend strip. An optional measured correction profile applies scale/offset, a support range and bad-pixel replacement for display only.

    Orientation is applied as clockwise rotation, then mirror, then flip; rows are produced by one inverse transform per scanline and a signed native stride.

    SIMD: NEON (ARM64) and SSSE3 (x86-64, runtime-detected) accelerate +/-1-stride rows and produce the same bytes as the scalar code, which handles every remaining case.

    Load bounded measured display corrections, never vendor factory tables.

    Steps: bounded read (8192-byte buffer) -> SHA-256 of the raw bytes -> strict parse -> completeness and range checks -> bad-pixel geometry check and linearization -> sort -> duplicate rejection -> byte copy to caller. On any failure errno is EINVAL, including read failures, whose original errno is not preserved; profile is then left untouched.

    Note
    The digest covers comments and whitespace too, so any byte change yields a new profile identity.

    Resolve one deterministic display window while retaining original samples.

    LWIR_SENSOR returns {0, 255} without reading samples. LWIR_FIXED copies the requested window. LWIR_PERCENTILE ranks valid display samples in a 65536-bin histogram. All thermal views then count invalid/below/above samples for diagnostics.

    Parameters
    frameImmutable combined frame, or image-only YUYV for LWIR_SENSOR.
    bytesExact size.
    widthNative width.
    heightNative height.
    optionsDisplay-only policy.
    rangeResolved bounds/clipping counts, valid only on success.
    Returns
    True for a supported rendering request. On failure errno is EINVAL for invalid arguments/options/profile/legend geometry, or ENODATA when a percentile view finds no valid sample.
    Warning
    Uses a static histogram: not re-entrant or thread-safe; call serially.

    Resolve one deterministic display window while retaining original samples.

    Percentile algorithm: histogram every valid uncorrected display value, then pick the values at 0-based ranks floor((samples-1) * percentile / 100) (lower nearest-rank) by scanning cumulative counts. The window is corrected afterwards, which is equivalent to ranking corrected values because correction is monotone. Afterwards every pixel is classified as invalid, below or above the window.

    Returns
    True on success; false with errno EINVAL for invalid input or ENODATA when a percentile view has no valid sample.
    Warning
    Not re-entrant: shares the static histogram.

    Emit one bounded Y/Cb/Cr scanline, without a full RGB or rotated frame.

    Resolves the row's first native pixel and stride once, then either copies the camera image (LWIR_SENSOR) or maps each display value through the window: invalid -> yellow, below -> cyan-blue, above -> magenta, otherwise palette colour; legend rows are overdrawn. RGB is converted with integer full-range BT.601 coefficients.

    Returns
    True on success; false with errno EINVAL for invalid input.
