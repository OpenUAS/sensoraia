    Detailed Description

    Tiny1-C vendor mailbox: bounded device-state snapshots and verified setting controls.

    The Tiny1-C exposes a command mailbox through a small register window:

    • status byte at 0x0200: 0 = idle/done, bit0 = busy, bits 0xfc = error class (0x08/0x10 unsupported, 0x14 invalid, anything else I/O error);
    • standard 8-byte command header written at 0x1d00 (the write executes it);
    • extended 16-byte header: bytes 0..7 written to 0x9d00 are only held, bytes 8..15 written to 0x1d08 trigger execution;
    • reply read at 0x1d00 + header length (0x1d08 standard, 0x1d10 extended).

    This module implements only that protocol. Transport is injected through struct lwir_state_io: the native driver backs it with Linux USBFS control transfers, host tests back it with fakes. No heap, no memcpy, no global state.

    Two independent entry families exist:

    • lwir_state_read(): read-only evidence snapshot taken after a capture, bounded by LWIR_STATE_BUDGET_MS and explicitly not frame-atomic;
    • lwir_state_control() / lwir_state_control_read(): one targeted write or read with read-back verification and a submitted-versus-verified result.

    Value ranges and units come from the vendor headers; they describe what the device accepts, not measured radiometric accuracy.

    ◆ lwir_state_field

    enum lwir_state_field

    Index of each queried device-state field; also the read order.

    Fields are read in this order, so earlier entries are the most likely to complete within LWIR_STATE_BUDGET_MS. Two-byte values are big-endian; ranges below are those accepted by lwir_state_read() validation.

    • LWIR_STATE_GAIN: gain select, 0 = low, 1 = high (TPD params, cmd 0x14/0x85 #5).
    • LWIR_STATE_FW_BUILD: firmware build, 64-byte device-info string (0x05/0x84 #5).
    • LWIR_STATE_FW_DATE: firmware date, 64-byte device-info string (0x05/0x84 #1).
    • LWIR_STATE_CHIP: chip identification, 64-byte device-info string (0x05/0x84 #0).
    • LWIR_STATE_SHUTTER: shutter status, two bytes each 0 or 1 (0x0c/0x83).
    • LWIR_STATE_DISTANCE: target distance, 128 units per metre, 0..32767 (TPD #0).
    • LWIR_STATE_REFLECTED_K: reflected temperature in kelvin, 230..900 (TPD #1).
    • LWIR_STATE_AMBIENT_K: ambient temperature in kelvin, 230..900 (TPD #2).
    • LWIR_STATE_EMISSIVITY: emissivity in 1/128, 1..128 (TPD #3).
    • LWIR_STATE_TRANSMITTANCE: atmospheric transmittance in 1/128, 1..128 (TPD #4).
    • LWIR_STATE_TNR: temporal noise reduction level, 0..3 (image params 0x14/0x83 #0).
    • LWIR_STATE_SNR: spatial noise reduction level, 0..3 (image #1).
    • LWIR_STATE_DDE: digital detail enhancement level, 0..6 (image #2).
    • LWIR_STATE_BRIGHTNESS: display brightness, 0..255 (image #3).
    • LWIR_STATE_CONTRAST: display contrast, 0..255 (image #4).
    • LWIR_STATE_AGC_MODE: automatic gain control mode, 0..5 (image #5).
    • LWIR_STATE_AGC_MAX_GAIN: AGC maximum gain, 0..255 (image #6).
    • LWIR_STATE_AGC_BOS: AGC brightness offset, 0..255 (image #7).
    • LWIR_STATE_AGC_ENABLE: AGC enable, 0 or 1 (image #8).
    • LWIR_STATE_MIRROR_FLIP: mirror/flip combination, 0..3 (image #9).
    • LWIR_STATE_FIELDS: number of fields, not a field.

    ◆ lwir_state_status

    enum lwir_state_status

    Outcome of one field read or one control operation.

    The numeric order is part of the evidence format: lwir_state_format() maps it to text by index.

    • LWIR_STATE_NOT_REQUESTED: zero value; nothing was attempted.
    • LWIR_STATE_OK: reply received and validated (or setting verified).
    • LWIR_STATE_UNSUPPORTED: device status error class 0x08 or 0x10.
    • LWIR_STATE_TIMEOUT: transfer returned -7, the budget ran out, or polling never saw the mailbox go idle.
    • LWIR_STATE_IO_ERROR: other negative or short transfer, or any other device error class.
    • LWIR_STATE_INVALID: device error class 0x14, implausible/out-of-range reply, unusable arguments/callbacks, or a control read-back mismatch.
    • LWIR_STATE_BUSY: the mailbox was not idle when a snapshot started; reported on the first field only, nothing was sent.
    • LWIR_STATE_SKIPPED: the snapshot stopped before reaching this field.
    • LWIR_STATE_CANCELLED: transfer returned -10 or the pause callback refused.

    Apply one setting or trigger FFC, then confirm it.

    Setters write the value and verify it by exact read-back within 1 s (gain: 5 s). FFC waits 3 s and an idle mailbox within 5 s, and reports acknowledgement only.

    Parameters
    ioTransport; all callbacks required.
    requestValidated with lwir_control_valid().
    resultAlways reset when non-NULL; see struct lwir_control_result.
    Returns
    True when completed (and verified for setters). False otherwise; check result->submitted before deciding anything about device state.
    Warning
    Never retry blindly after a false return with submitted set.

    Apply one setting or trigger FFC, then confirm it.

    Returns
    True when the setter was verified or FFC was acknowledged. False on invalid input, budget overflow or any failed step; result->submitted tells whether the device may already have acted.
    • Budget: 1 s; gain and FFC 5 s (gain may involve internal correction).
    • Always wait for an idle mailbox first so a pending command is not overwritten.
    • FFC: standard command 0d c1 02 (OOC+B combined update, not shutter open/close) at 0x1d00, then a fixed 3 s wait (300 x 10 ms) mirroring the vendor's special 3000 ms poll delay, then an idle check. Result is an acknowledgement only; verified stays false.
    • Setters: SET subcommand = getter + 0x40 (0x83->0xc3 image, 0x85->0xc5 TPD), value big-endian in header bytes 6..7 (verified against vendor reference source). Held half to 0x9d00, trigger half to 0x1d08, wait idle, read back, and mark verified only on an exact match.
      Warning
      After a false return with submitted set, never replay the command; read the setting back to learn the device state.

    A fixed header records provenance and two constant caveats: device_state_bench=unverified and device_state_frame_atomic=0. For a requested snapshot, each field adds three lines: status name, reply hex ("unknown" unless OK) and "transport_error,device_status" so failures stay diagnosable.

    ◆ lwir_state_read()

    void lwir_state_read ( const struct lwir_state_io * io,
    struct lwir_device_state * state )

    Take a best-effort, read-only snapshot of all device-state fields.

    Total time is bounded by LWIR_STATE_BUDGET_MS. Unsupported or invalid fields are recorded and the next field is tried; timeout, I/O error or cancellation stops the snapshot and leaves the rest LWIR_STATE_SKIPPED.

    Parameters
    ioTransport; an unusable table marks field 0 LWIR_STATE_INVALID.
    stateFully overwritten; NULL is ignored.
    Note
    Not frame-atomic: values are read after the frame and may differ from those in effect at exposure.
    Warning
    An aborted command may leave the mailbox busy, so the next snapshot can report LWIR_STATE_BUSY.

    Take a best-effort, read-only snapshot of all device-state fields.

    Algorithm:

    1. Zero the state, mark it requested and every field skipped.
    2. Refuse to start unless the mailbox status is idle (0), so a command still running from an earlier aborted snapshot is not clobbered.
    3. For each field in table order: write the command header (standard at 0x1d00, or extended as held half at 0x9d00 plus trigger half at 0x1d08), poll 0x0200 up to 32 times at <= 10 ms intervals until idle, read the reply at 0x1d00 + header length and validate it. Unsupported/invalid fields continue with the next field because the device is still responsive; timeout, I/O error and cancellation stop the snapshot since further transfers would only burn budget or hit a busy mailbox.
      Note
      Failures are reported only through state; field 0 carries LWIR_STATE_INVALID for an unusable io or LWIR_STATE_BUSY for a busy mailbox.
