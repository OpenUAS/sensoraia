    Detailed Description

    JPEG EXIF updates for USHER flight and thermal-capture provenance.

    Existing JPEG markers are copied while prior EXIF is replaced by a standards compliant APP1 block. Default in-place updates avoid temporary files and leave equal-position image bytes untouched. IMAGE_EXIF_ATOMIC_REPLACE selects the older sibling-file/fsync/rename method when original-file retention is more important. In-place writes are not atomic; interrupted mutation can damage the JPEG. Neither method promises full power-loss durability, since the parent directory is not synced.

    Write flight provenance and an available object-detection result in one metadata transaction.

    Parameters
    filenameExisting JPEG; the caller exclusively owns metadata updates to this path.
    shotPose used for geotags, already exposure-aligned when request is supplied.
    delayFallback request-to-arrival latency in seconds; negative means unknown.
    compensateNonzero enables the legacy position estimate; use zero for exposure-aligned pose.
    timingOptional arrival evidence and shared bounded observation-time pose.
    requestOriginal FC request to preserve alongside an aligned pose, or NULL.
    uncertainty_mNonnegative ground-position margin recorded when request is supplied.
    objectsOptional already-produced object summary, or NULL; no inference runs here.
    Returns
    Zero on publication, -1 on invalid metadata, JPEG or storage failure.

    Compressed image data is copied, not decoded/re-encoded. Combining tags avoids a second full-file rewrite but does not remove the camera's original JPEG write. Validate frame identity before calling. In-place updates retain the inode; optional atomic replacement changes it. In-place I/O failures can damage the file.
