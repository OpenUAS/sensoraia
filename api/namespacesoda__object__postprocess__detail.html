    ◆ append_detection_csv()

    bool soda_object_postprocess_detail::append_detection_csv ( const std::string & csv_path,
    const std::string & image_basename,
    const ObjectDetection & detection )

    Append one CSV row for detection to csv_path, safe against concurrent SODA processes racing on the same file (usher can run multiple worker threads' finish_image() close together, each spawning its own SODA child).

    Header-or-not is decided with O_CREAT|O_EXCL: whichever process wins that race writes header+row together in a single write(); every loser falls back to a plain O_APPEND open and writes only its own row. Each row (and the header+row for the winner) goes out as exactly one write() call, which POSIX guarantees is atomic against other O_APPEND writers on the same file as long as it stays under PIPE_BUF – comfortably true for these rows.

    Parameters
    csv_pathShared CSV path.
    image_basenameSource JPEG basename.
    detectionEXIF-derived hit summary.
    Returns
    True when exactly one complete row/header+row is written.

    ◆ kAsciiCommentPrefixSize

    size_t soda_object_postprocess_detail::kAsciiCommentPrefixSize = 8
    		constexpr

    Matches image_exif.c's write_tagged_comment(): an 8-byte ASCII-charset prefix precedes the text payload in EXIF_TAG_USER_COMMENT, and the tagged record itself is introduced by "\n<TAG>\n". The entry is zero-filled before being written and sized one byte past the visible text (image_exif.c's replace_tag()/write_tagged_comment()), so a trailing NUL is present in practice, but entry->size (not strlen()) is used regardless, to stay correct even if that trailing byte is ever not zero.
