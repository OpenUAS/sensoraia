    Detailed Description

    Tiny1-C vendor mailbox protocol: snapshot reads, controls and evidence text.

    Transport-agnostic implementation of the protocol summarised in lwir_state.h. Every operation is driven by an absolute deadline: each transfer timeout is the remaining budget capped at 50 ms, and every poll loop is bounded both by an iteration cap and by that deadline, so a stuck device cannot stall the capture path. Storage is caller-owned or on the stack; no heap, no memcpy.

    ◆ lwir_state_control()

    bool lwir_state_control ( const struct lwir_state_io * io,
    const struct lwir_control_request * request,
    struct lwir_control_result * result )

    Apply one setting with read-back verification, or trigger FFC.

    Apply one setting or trigger FFC, then confirm it.

    Returns
    True when the setter was verified or FFC was acknowledged. False on invalid input, budget overflow or any failed step; result->submitted tells whether the device may already have acted.
    • Budget: 1 s; gain and FFC 5 s (gain may involve internal correction).
    • Always wait for an idle mailbox first so a pending command is not overwritten.
    • FFC: standard command 0d c1 02 (OOC+B combined update, not shutter open/close) at 0x1d00, then a fixed 3 s wait (300 x 10 ms) mirroring the vendor's special 3000 ms poll delay, then an idle check. Result is an acknowledgement only; verified stays false.
    • Setters: SET subcommand = getter + 0x40 (0x83->0xc3 image, 0x85->0xc5 TPD), value big-endian in header bytes 6..7 (verified against vendor reference source). Held half to 0x9d00, trigger half to 0x1d08, wait idle, read back, and mark verified only on an exact match.
      Warning
      After a false return with submitted set, never replay the command; read the setting back to learn the device state.

    Render a snapshot as key=value evidence lines for the JPEG APP14 segment.

    Returns
    Bytes written excluding the NUL; 0 on NULL/zero-sized output, overflow, or a corrupt status/length (output may then hold a truncated prefix).

    A fixed header records provenance and two constant caveats: device_state_bench=unverified and device_state_frame_atomic=0. For a requested snapshot, each field adds three lines: status name, reply hex ("unknown" unless OK) and "transport_error,device_status" so failures stay diagnosable.

    Note
    Returning 0 rather than truncating lets the caller refuse incomplete evidence.

    ◆ lwir_state_read()

    void lwir_state_read ( const struct lwir_state_io * io,
    struct lwir_device_state * state )

    Read all fields of struct lwir_device_state within LWIR_STATE_BUDGET_MS.

    Take a best-effort, read-only snapshot of all device-state fields.

    Algorithm:

    1. Zero the state, mark it requested and every field skipped.
    2. Refuse to start unless the mailbox status is idle (0), so a command still running from an earlier aborted snapshot is not clobbered.
    3. For each field in table order: write the command header (standard at 0x1d00, or extended as held half at 0x9d00 plus trigger half at 0x1d08), poll 0x0200 up to 32 times at <= 10 ms intervals until idle, read the reply at 0x1d00 + header length and validate it. Unsupported/invalid fields continue with the next field because the device is still responsive; timeout, I/O error and cancellation stop the snapshot since further transfers would only burn budget or hit a busy mailbox.
      Note
      Failures are reported only through state; field 0 carries LWIR_STATE_INVALID for an unusable io or LWIR_STATE_BUSY for a busy mailbox.
