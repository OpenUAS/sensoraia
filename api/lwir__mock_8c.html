    Detailed Description

    Development replay: convert an ordinary JPEG into LWIR evidence (LWIR_ENABLE_MOCK).

    Two modes:

    • layer only: keep the source's compressed bytes and insert LWIRSIM1 APP15 temperature chunks derived from luminance;
    • full: decode, build a combined image+temperature frame, re-render it with the normal LWIR renderer, and carry the source EXIF across. An existing embedded temperature layer is always reused rather than synthesized. Output goes to a same-directory temporary file, is fsynced, then published without overwriting unrelated files. All buffers are static (no heap).

    Parameters

    outputDestination stream.
    widthTemperature width.

    Returns
    True if everything was copied; false on a non-JPEG source or any I/O error.

    Each chunk is "LWIRSIM1", width, height, byte offset (all u32 LE) and up to 65000 data bytes, keeping the segment under JPEG's 65535-byte limit. Chunks go right after SOI; the remaining source bytes, including its own segments and compressed pixels, are copied unchanged.

    ◆ lwir_process_mock()

    int lwir_process_mock ( const char * input_path,
    const char * output_path,
    bool layer_only )

    Produce mock LWIR evidence from input_path at output_path.

    Preserve embedded temperatures or attach explicitly synthetic evidence.

    Returns
    0 on success, -1 on any failure.

    Steps: open and identify the source; read any embedded layer; decode if needed; write a mode-matched temporary file next to the output; check that the source did not change meanwhile; publish with link() (fails if the name exists) or, in place, rename() after confirming the path still names the same inode; finally fsync the directory.

    Warning
    -1 is also returned if only the final directory fsync fails, after the file has already been published.
