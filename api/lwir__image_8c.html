    Detailed Description

    LWIR JPEG encoder and durable no-overwrite file publisher.

    Implements lwir_image.h. Every photo goes through one static libjpeg workspace so no heap allocation is made per photo by this module (libjpeg still allocates internally). Consequently the encoder is single-threaded and not re-entrant.

    Marker order inside each JPEG, all before the first scanline:

    1. APP14 "LWIREV02" provenance text (only with evidence).
    2. APP1 EXIF with the sensor-capture tag (only with evidence, live frames).
    3. APP15 thermal chunks (combined frames only). libjpeg may emit its own JFIF APP0 before these, so readers must scan markers rather than expect APP1 directly after SOI.

    Codec errors longjmp from jpeg_failure() back to encode_jpeg() with errno = EIO. Publication writes a temporary, fsyncs, link()s and fsyncs the directory; see publish().

    Durably publish a JPEG or raw companion under a new name.

    Parameters
    pathFinal destination; must not exist.
    frameFrame to encode or copy.
    bytesExact frame size (half size for image-only JPEG output).
    widthNative width.
    heightNative height.
    syntheticTrue for replayed/simulated frames (JPEG only).
    rawTrue writes frame verbatim instead of encoding a JPEG.
    evidenceOptional provenance (JPEG only).
    renderOptional display policy (JPEG only).
    Returns
    True when the file is complete, named and the directory synced. On false, errno holds the first failure (later cleanup does not overwrite it) and path does not exist: a name this call already linked is removed again.

    Sequence: mkstemp "PATH.part.XXXXXX" -> write -> fflush + fsync -> link() to path -> fsync directory -> unlink temporary -> fsync directory. link() fails with EEXIST instead of replacing an existing file (unlike rename()), so publication is atomic and never overwrites. The temporary is removed on every path. Because link() refuses existing names, a name removed on rollback is always one this call created, never someone else's file.

    Note
    mkstemp creates the file owner-only (0600); the linked name keeps that mode.

    Parameters
    encoderStarted compressor; markers must precede the first scanline.
    widthNative frame width.
    heightNative frame height.
    display_widthEncoded width after orientation.
    display_heightEncoded height after orientation.
    syntheticTrue for replayed/simulated frames.
    evidenceOptional provenance; NULL writes no APP14 or EXIF at all.
    renderResolved display policy (never NULL here).
    rangeWindow and clipping counts from lwir_render_prepare().
    Returns
    Zero on success, otherwise the errno value the encoder owner must publish: ENOSPC when the text exceeds the fixed evidence buffer, EINVAL when the sensor-capture record cannot be encoded or serialized.

    Teardown stays with the owner so marker failures retain cleanup/error ordering. Builds the APP14 text in several bounded snprintf steps; each step checks truncation so a partial key=value record is never emitted.
