    Detailed Description

    Tiny1C/TDK acquisition and Tiny1C state, without image or mission logic.

    This interface is the only boundary between LWIRcam and the camera hardware. It delivers raw camera-layout frames plus timing evidence; image conversion, calibration, geolocation and mission policy live elsewhere.

    Supported cameras
    • Tiny1-C (USB 0bda:5840): combined YUYV transport of 256x384 pixels, i.e. a 256x192 image plane followed by a 256x192 temperature plane holding Kelvin*64 little-endian values; 196608 bytes per frame at about 25 fps. Its separate 256x192 image-only UVC mode is not combined data and is not used.
    • TDK (USB 5474:5411): 640x512 image-only YUYV; no temperature plane.
    Backend
    Capture runs in lwir_device_v4l2.c directly on the Linux uvcvideo kernel driver with V4L2 MMAP buffers and usbfs control requests for Tiny1-C state.
    Ownership model
    Every object is caller-owned storage; the backend performs no heap allocation. A session owns one V4L2 descriptor (held under an exclusive flock) and up to LWIR_VIDEO_BUFFERS kernel buffers mapped into the process. Mapped buffers are only borrowed between dequeue and requeue; callers never see their addresses and receive copies instead.
    Threading
    A session is not thread-safe: one thread must own all calls on it. The only cross-context input is the borrowed sig_atomic_t cancellation flag, which may be set from a signal handler or another thread and is polled at least every 25 ms while waiting.
    Lifecycle invariants
    • Zero-initialize, lwir_device_open(), acquire/discard/state calls, then lwir_device_close(). Close before reopening.
    • A fatal kernel or protocol error poisons the session (EIO) until it is closed and reopened; no partial recovery is attempted.
    • The eight-frame startup qualification runs once per USB power instance, remembered across reopen and process restart, and is never repeated for later requests, gaps, invalid frames or reconnection of the same instance.

    Copy a qualified, fresh camera-layout frame into caller-owned storage.

    Loop structure, each iteration bounded by a 25 ms poll() slice so that cancellation and the deadline are noticed promptly:

    1. poll() for a filled buffer; POLLERR/POLLHUP/POLLNVAL (for example an unplugged camera) poison the session.
    2. Dequeue one buffer and read the host clock immediately.
    3. Grade the frame in increasing strictness:
      • usable: structurally valid, recent, correct sequence; feeds the startup qualification counter even when it predates the request.
      • valid: additionally started at or after the request (freshness).
      • scene_valid: additionally passes the optional scene check.
    4. For non-MONOTONIC clocks freshness is unknowable, so the first good frame triggers a one-time drain of all already-queued buffers; the next frame is then certainly produced after the request.
    5. Accept when the instance is qualified (eight good frames), optional settling holds, and on first startup only, warmup_ms has elapsed.
    6. Copy what is needed and snapshot sequence/timestamp/flags, then requeue. The order matters: after QBUF the kernel may overwrite both pixels and metadata.
    7. Persist the startup marker once qualification and warmup are complete.

    Settling uses destination as the previous-image store: the image plane of each scene-valid frame is copied there and the next frame is compared against it, so no extra buffer is needed. The temperature plane is copied only for the accepted frame.

    Returns
    True with a fresh frame in destination.
    Errors
    EINVAL arguments/aliasing; EIO poisoned session or poll error; ETIMEDOUT deadline, including completion that would land after it; EINTR cancelled; kernel errno from failed ioctls (session then poisoned).
    Warning
    On failure destination may contain partial or settling data and must be ignored.

    ◆ lwir_device_close()

    void lwir_device_close ( struct lwir_device * device)

    Close an initialized session; safe repeatedly and preserves errno.

    Native failed unmaps remain owned for a subsequent close and prevent reopening. Linux descriptor-close errors are never retried on a reused number.

    Close an initialized session; safe repeatedly and preserves errno.

    1. STREAMOFF returns all buffers from the driver queue to user space.
    2. munmap each mapping. A failed unmap keeps its entry marked as mapped and the session struct is not cleared, so a later close retries it and lwir_device_open() refuses with EBUSY rather than losing track of memory the process still maps.
    3. REQBUFS with count 0 frees the kernel buffers when the driver allows it.
    4. close() the descriptor exactly once. Its state is cleared first and a close error is only logged: Linux frees the number even on error, so retrying could close an unrelated descriptor opened by another thread.

    Errors of STREAMOFF/REQBUFS are deliberately ignored; there is no better recovery than continuing teardown, and closing the descriptor ends the stream regardless.

    Parameters
    deviceSession to release; NULL and already-closed sessions are accepted.
    Note
    errno is preserved so callers can close on an error path without losing the original cause.

    bool lwir_device_open ( struct lwir_device_options * options,
    struct lwir_device * device )

    Open/start a bounded camera-specific combined or image-only YUY2 stream.

    Parameters
    optionsRequested policy; native dimensions are written on success.
    deviceEmpty caller-owned session, closed on failure.
    Returns
    True on success; errno describes failure. Close before reopening.
    Errors
    EINVAL invalid options; EBUSY session still owns a descriptor or mapping; ENODEV no matching camera; EEXIST more than one matching camera during a scan; EWOULDBLOCK another process holds the camera; ENOTSUP unsupported format or image-only camera when thermal data is required; ETIMEDOUT or EINTR deadline or cancellation; other values come from the kernel.

    Open/start a bounded camera-specific combined or image-only YUY2 stream.

    1. Validate options and refuse while the session still owns anything, including mappings kept after a failed munmap (EBUSY).
    2. Compute one absolute deadline covering discovery and setup.
    3. With an explicit device path, probe only that node. Otherwise probe /dev/video0..63. A second matching camera is an error (EEXIST) rather than "first wins": with two cameras attached the choice would depend on enumeration order, so the caller must disambiguate with a serial or path. Each match holds its own flock until the scan decides.
    4. Read the startup marker, then set up streaming.

    Every failure after a successful probe closes the session, so the caller never has to clean up after a false return.

    Returns
    True when streaming; errno set otherwise (see lwir_device.h).
