    Detailed Description

    READY/SHOT/OK process ownership without model-analysis semantics.

    Each backend keeps its own state, rather than sharing a detector's process globals. This supervisor qualifies the command channel and saved file; exposure identity and analysis results are checked by their respective consumers.

    Request one saved photograph and qualify its acknowledgement/file.

    Parameters
    [in,out]pipeRunning worker owned by the calling backend.
    [out]filenamePrivate .pending path; consume it only after successful return.
    [in]capacityWritable bytes in filename, including its terminator.
    [in]numberNonnegative photo number used in the backend's filename.
    Returns
    Zero for an exact OK response and a nonempty regular file, otherwise -1.

    Absolute paths avoid dependence on the child's working directory. Newlines are rejected because the protocol is line-framed. A failed exchange closes/reaps the worker rather than pairing a late response with another shot. A later request starts a replacement worker only after the previous owner exits. The caller finishes metadata and calls usher_complete_photo before final-name publication.

    Warning
    This does not decode JPEG pixels, prove exposure timing, or establish valid inference. A failed shot is never automatically replayed.

    ◆ imx500_pipe_start()

    int imx500_pipe_start ( struct imx500_pipe * pipe)

    Replace any owned worker and require its exact READY response.

    Parameters
    [in,out]pipeInitialized state with live command/model/directory strings.
    Returns
    Zero after readiness, otherwise -1 with newly acquired resources closed.

    The child owns the camera. Readiness includes its model-specific warm-up, not just successful process creation. Existing owned work is stopped before spawning, preventing a second child from competing for the same sensor.

    Note
    No analysis sidecar or object/LOOM result is read by this interface.

    ◆ imx500_pipe_stop()

    void imx500_pipe_stop ( struct imx500_pipe * pipe)

    Close the channel, allow an exit grace period, then kill/reap if needed.

    Parameters
    [in,out]pipeInitialized state; NULL is ignored.

    Closing the command channel lets a healthy worker finish normally. Reaping keeps stale process state from being mistaken for an available camera. Monotonic grace periods bound polling; an unconfirmed exit retains PID ownership and prevents a replacement worker. Scheduling and kernel stalls are not preempted.

    Note
    Repeated stops are harmless once the PID and descriptor are cleared.
