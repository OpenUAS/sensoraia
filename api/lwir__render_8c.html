    Detailed Description

    Display window resolution and per-scanline Y/Cb/Cr rendering of LWIR frames.

    Input is the Tiny1-C combined frame: the first half is the YUYV image plane (Y0 U Y1 V per pixel pair, chroma shared by the pair), the second half the thermal plane of little-endian uint16 Kelvin*64 codes (raw/64 - 273.15 = degC as reported by the device, calibration unverified). Codes 0 and 65535 are endpoint/invalid codes. LWIR_SENSOR also accepts an image-only buffer of half that size.

    Output is one JPEG-ready scanline of interleaved full-range BT.601 (JFIF) Y/Cb/Cr bytes per call. Orientation is resolved once per scanline by row_source() into a first native pixel and a signed stride, so the raw thermal bytes are never reordered or copied.

    Optional profile corrections, bad-pixel replacement and denoise act on display values only. The scalar code is the reference; NEON (ARM64) and SSSE3 (x86-64) cover common +/-1-stride cases and must yield identical bytes, falling back to scalar for transposed rows, tails, profiles, denoise, the iron palette and legend rows.

    Storage: no heap. The percentile histogram is a 256 KiB static array, chosen over the stack (too large for thread stacks) and heap (project policy); this makes lwir_render_prepare() non-re-entrant.

    Apply the profile's linear display correction.

    round_half_up(raw * scale_ppm / 1e6) + trunc(offset_mk * 64 / 1000): one kelvin is 64 raw units, so one millikelvin is 0.064 raw. 64-bit intermediates avoid overflow. For the accepted positive scale the mapping is monotone non-decreasing, so ranking raw values (percentiles) and correcting afterwards preserves order.

    Parameters

    Returns

    Produce the uncorrected display value of one native pixel.

    1. Ordinary pixels use original_sample().
    2. Listed bad pixels take the median of their usable 4-connected neighbours (bad, endpoint and out-of-support neighbours are skipped; edges have fewer candidates).
    3. If denoise_raw is set, average the value with those of its 8 neighbours whose original sample lies within +/-denoise_raw of it (edge-preserving: neighbours across a stronger edge are excluded), rounded to nearest.

    Validate a render request and resolve its display window and counts.

    Resolve one deterministic display window while retaining original samples.

    Percentile algorithm: histogram every valid uncorrected display value, then pick the values at 0-based ranks floor((samples-1) * percentile / 100) (lower nearest-rank) by scanning cumulative counts. The window is corrected afterwards, which is equivalent to ranking corrected values because correction is monotone. Afterwards every pixel is classified as invalid, below or above the window.

    Returns
    True on success; false with errno EINVAL for invalid input or ENODATA when a percentile view has no valid sample.
    Warning
    Not re-entrant: shares the static histogram.

    Render one oriented display row as interleaved Y/Cb/Cr.

    Emit one bounded Y/Cb/Cr scanline, without a full RGB or rotated frame.

    Resolves the row's first native pixel and stride once, then either copies the camera image (LWIR_SENSOR) or maps each display value through the window: invalid -> yellow, below -> cyan-blue, above -> magenta, otherwise palette colour; legend rows are overdrawn. RGB is converted with integer full-range BT.601 coefficients.

    Returns
    True on success; false with errno EINVAL for invalid input.

    unsigned display_height,
    unsigned row,
    ptrdiff_t * step )
    		static

    Map a display row to its first native pixel and per-column native stride.

    Display = flip(mirror(rotate_cw(native))), so the inverse is applied in reverse order. For display (x, row):

    1. Undo flip: vertical = flip ? display_height-1-row : row.
    2. Undo mirror: rotated column x' = horizontal + direction*x, with horizontal = mirror ? display_width-1 : 0 and direction = mirror ? -1 : +1.
    3. Undo clockwise rotation of (x', vertical) into native (nx, ny):
      • 0: nx = x', ny = vertical -> stride +direction
      • 90: nx = vertical, ny = height-1-x' -> stride -direction*width
      • 180: nx = width-1-x', ny = height-1-vertical -> stride -direction
      • 270: nx = width-1-vertical, ny = x' -> stride +direction*width Native index ny*width + nx is affine in x, so the result is first + x*step.
        Parameters
        widthNative width.
        heightNative height.
        optionsOrientation policy (validated).
        display_widthOriented width.
        display_heightOriented height.
        rowDisplay row, < display_height.
        stepOutput signed native stride per display column.
        Returns
        Native raster index of display column 0.
        Note
        With even native width, forward (+1) rows start at an even native index and reversed (-1) rows start at an odd one, so pixel - 7 is even and 8-pixel SIMD blocks always begin on an intact YUYV pair.

    Copy the camera's own YUYV image row into Y/Cb/Cr output (LWIR_SENSOR).
