    Detailed Description

    JSON reader, writer and DOM utilities for Linux C11 with a C++11-compatible API.

    Strict parsing validates RFC 8259 grammar and Unicode scalar values in UTF-8. The input need not be terminated, aligned or padded and is never modified. Decoded strings and unchanged numeric tokens are owned by the returned DOM. Duplicate names and their order are preserved; jsonbourne_obj_getn_unique() rejects ambiguous lookups. Embedded NULs are supported through explicit byte lengths.

    Parsing and cloning make one allocation, released with free() when the default allocator is used. Custom allocators must provide malloc-compatible alignment and own their corresponding release policy. jsonbourne_read_buf(), jsonbourne_read_measure(), jsonbourne_read_validate() and the *_buf writers do not allocate. Input, DOM and output buffers must not overlap and must remain stable throughout each operation. Allocator callbacks must not mutate input or DOM data. Independent calls share no mutable state and may run concurrently.

    JSONBOURNE_READER_DEPTH_LIMIT bounds reader nesting and fixed traversal storage. JSONBOURNE_WRITER_DEPTH_LIMIT bounds writer/copy traversal and defaults to the reader limit. Both are positive hard limits, initially 999; zero does not mean unlimited. Embedded consumers should select smaller application-specific limits when compiling jsonbourne.c. Runtime limits additionally bound input, total DOM bytes, decoded string bytes and value count before allocation. SIMD is automatic for baseline x86-64 SSE2 and AArch64 NEON; define JSONBOURNE_DISABLE_SIMD=1 for a scalar build. Every vector load is within the supplied input extent. Normal -O2/-O3 suffices; no fast-math or SSSE3 is needed.

    Writers validate accessible DOM structures, UTF-8, numbers, list lengths and cycles. All output sizes INCLUDE the terminating NUL, matching the original API. Numbers keep their decimal spelling and precision. Relaxed hexadecimal tokens are converted exactly, up to JSONBOURNE_MAX_HEX_DIGITS significant hex digits; larger conversions fail rather than overflow. The legacy relaxed nonfinite writer policy maps NaN to 0 and infinities to signed DBL_MAX text. Compile jsonbourne.c once with the desired build options and link its object. Public names follow Yuan conventions, but the DOM layout, flag bits and writer lengths are JSONbourne-specific rather than Yuan ABI compatible. Pretty-print indentation/newlines must contain JSON whitespace only.

    Why tokens and lengths are preserved
    Keeping decimal text avoids rounding large integers through binary floating point. Explicit byte lengths distinguish embedded NULs from terminators, and preserving duplicate keys lets the application decide whether ambiguity is acceptable instead of silently discarding input.
    Precondition
    Input, DOM nodes, linked entries and output storage must refer to valid, accessible memory for their advertised lifetimes and extents. Structural validation detects malformed lists and cycles, not arbitrary invalid pointers.
    Note
    Select compile-time options when building jsonbourne.c; defining them only in a client does not change the linked implementation's storage limits.
