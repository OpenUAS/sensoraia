    Detailed Description

    Strict loader for measured LWIR display-correction profiles.

    Parses a flat INI file whose format key is "LWIR_CORRECTIONS_V1": serial, gain label, width, height, scale_ppm (500000..1500000), offset_mk (-50000..50000), range_min_raw/range_max_raw (supported raw code range, excluding the endpoint codes 0 and 65535), bad_pixel_count and bad_pixel_0..bad_pixel_N-1 as "column,row" pairs.

    The renderer applies these corrections to display pixels only; native temperatures, measurements and stored APP15 data are never altered. The SHA-256 of the exact file bytes becomes the profile identity recorded in each JPEG's provenance text.

    Invariants: the whole file is bounded to 8192 bytes; all fields are mandatory and unique; bad pixels are bounded by LWIR_MAX_BAD_PIXELS, inside the profile geometry, sorted ascending and duplicate-free. The caller's struct is written only after every check passed (all-or-nothing), using a byte loop rather than memcpy per project policy.

    ◆ lwir_profile_load()

    bool lwir_profile_load ( const char * path,
    struct lwir_profile * profile )

    Load and fully validate a profile; see lwir_render.h.

    Load bounded measured display corrections, never vendor factory tables.

    Steps: bounded read (8192-byte buffer) -> SHA-256 of the raw bytes -> strict parse -> completeness and range checks -> bad-pixel geometry check and linearization -> sort -> duplicate rejection -> byte copy to caller. On any failure errno is EINVAL, including read failures, whose original errno is not preserved; profile is then left untouched.

    Note
    The digest covers comments and whitespace too, so any byte change yields a new profile identity.

    Unlike the provenance reader, unknown keys are errors: a profile changes rendered output, so a misspelled key must not be silently ignored.
