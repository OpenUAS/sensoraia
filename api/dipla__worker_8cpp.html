    Detailed Description

    Keep IPC responsive while one planner owns the survey and retained route.

    Two threads divide the work by ownership, not by algorithm:

    • The calling thread validates packets, admits observations, and replies from small route snapshots. It never reads or mutates the dense GP covariance.
    • The planner thread consumes the bounded FIFO in order, conditions the GP, and computes at most one completed route for each requested chunk token. Credit-aware SHOT separately acknowledges assimilation so its owner can bound new measurements without blocking packet validation or dropping evidence.

    Three identities answer different questions. The session token names the requested route chunk; survey_epoch names the continuing GP experiment; generation identifies a completed route within that chunk. An active START changes the chunk without erasing observations. STOP ends the survey, and the next START advances the epoch so its first observation gets a new GP.

    Why retain routes?
    A waypoint retrieval is not a waypoint arrival. Only the flight controller knows when its path is complete and when to request another chunk. Letting every pose trigger a new route would move the targets while they are followed. Whole-plan replies copy one generation; legacy point replies pin all eight retrieval slots so a single cycle cannot assemble a patchwork of routes.
    When adjusting timing or capacity
    Accepted measurements are evidence, not replaceable planning suggestions. Queue overflow fails the survey rather than quietly losing evidence, and freshness is measured from receipt, not from the end of expensive processing. Keep those rules intact when changing cadence, queue size, or reply handling.
    Warning
    This is a trusted local SOCK_SEQPACKET ABI, not the UART protocol. Socket calls and planner cancellation do not provide hard real-time bounds; the owning process must still supervise a stalled or failed worker.
