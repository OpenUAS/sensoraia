    Detailed Description

    Shared FC/MORA byte-stream UART framing, messages and payload layouts.

    This is the shared FC/MORA contract: commands and replies cross only the UART datastream. Both peers compile these message IDs, payload sizes and layouts; camera implementation, storage and capture scheduling are not part of the wire API. Multi-byte fields use the shared native layout; both peers must be upgraded together. The unions are serialization storage, not portable network byte order. There is no protocol-wide version field; the separate MORA survey extension declares its own version but is not negotiated by the FC.

    |STX|length|message ID|payload (length-5 bytes)|Checksum A|Checksum B|

    Length counts the entire frame. The checksum covers length, message ID and payload:

    usher_ck_a = usher_ck_b = length
    for each byte b in message ID followed by payload
    usher_ck_a += b;
    usher_ck_b += usher_ck_a;

    void parse_usher ( struct usher_transport * t,
    uint8_t c )

    Consume one byte from a USHER UART stream.

    Parameters
    tPersistent parser state for that stream.
    cNewly received byte.

    Frames may be arbitrarily split across calls. On a valid complete frame this sets t->msg_received and leaves the decoded bytes in t->payload. The caller must dispatch the message and clear that flag before supplying bytes for the next frame.

    Warning
    This function is not thread-safe. Serialize access to each t instance and do not alter its fields while a frame is in progress.

    Consume one byte from a USHER UART stream.

    Checksums cover the length, message ID, and payload bytes. A complete, valid frame sets t->msg_received; the caller must clear that flag after dispatching. Any framing or checksum error increments t->error and resets the state machine, avoiding a poisoned partial frame affecting later traffic.

    Warning
    t must remain valid and unchanged by another thread for the duration of a frame; this parser intentionally contains no synchronization.
